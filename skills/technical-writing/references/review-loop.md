# Review Loop

Use this file when reviewing or revising documentation.

Run these passes in order. Fix high-level problems before polishing sentences.

## Pass 1: Document type fit

Ask:
- What is the reader trying to do?
- Does the current document type match that goal?
- Is the page trying to teach, solve, explain, and reference at the same time?

Common fixes:
- Split a mixed page into learning, troubleshooting, and reference sections or pages.
- Rewrite the opening so the reader knows what this page is for.
- Remove content that belongs in another document type and replace it with a link.

## Pass 2: Information architecture

Ask:
- Is the value clear near the top?
- Is there one main goal per page?
- Are headings predictable, parallel, and searchable?
- Are prerequisites, overview, steps, verification, and links placed where readers expect them?

Common fixes:
- Add an overview under the title.
- Move background below the value statement.
- Break out a separate page when the topic is too broad.
- Rename headings to match reader intent rather than internal jargon.

## Pass 3: Sentence quality

Ask:
- Is the actor clear?
- Can long or passive sentences be rewritten?
- Are vague nouns replaceable with concrete verbs?
- Is the Korean natural and consistent?

Common fixes:
- Convert passive voice to direct instructions.
- Replace abstract nouns with actions.
- Remove filler and meta-discourse.
- Normalize terminology, abbreviations, and product names.

## Final verification

- Re-check commands, paths, flags, examples, API names, env vars, screenshots, and links against source material.
- Call out anything unverified instead of presenting it as fact.
