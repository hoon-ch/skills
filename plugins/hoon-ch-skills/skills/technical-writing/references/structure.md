# Structure

Use this file when organizing a page or a larger document set.

## One thing per page

- Keep each page centered on one primary reader goal.
- If headings need to go deeper than `####`, split the page.
- If several concepts need a home page, create an overview page that links outward.
- Prefer specific topics over broad catch-all pages.

## Value first

- Start with what the reader will achieve or understand.
- Delay history, implementation detail, and secondary background until after the reader sees the payoff.
- Avoid feature dumping before explaining why the feature matters.

## Strong titles

- Put the core keyword in the title.
- Keep titles concise and literal.
- Use one title style consistently across sibling pages.
- Make the title readable in search results and sidebars.

## Overview near the top

- Add a short overview right under the title.
- Answer: what is this, who is it for, and what can the reader do after reading?
- Treat the overview as both an abstract and a search snippet.

## Predictable flow

- Reuse section names and section order when documents of the same type are related.
- Keep headings parallel.
- Present information in the order the reader expects to consume it.
- Use the same term for the same concept across the page and across the doc set.

## Enough background

- Define new concepts before depending on them.
- Explain behavior conditions, edge cases, units, defaults, and timing when those details affect correctness.
- Link out when deeper explanation belongs elsewhere, but do not omit the minimum context needed to avoid confusion.

## Cross-linking

- Link from learning docs to reference and troubleshooting.
- Link from troubleshooting to the relevant reference or explanation pages.
- Link from overview pages to deeper leaf pages.
- Add links only when they help the next decision or next action.
